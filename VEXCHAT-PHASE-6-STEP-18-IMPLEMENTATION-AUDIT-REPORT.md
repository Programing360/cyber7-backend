## 5. Security Controls Implemented

1. **Environment Guard:** Proxy executes only when `process.env.VERCEL_ENV === "preview"`. In production or other environments, returns immediate 404 without reading headers or body.
2. **Fail-Closed Configuration:** If `BACKEND_BYPASS_SECRET` or `BACKEND_PREVIEW_UPSTREAM_URL` is absent, returns 500.
3. **Strict Upstream Validation:** Validates that `BACKEND_PREVIEW_UPSTREAM_URL` uses `https:`, host is exactly `cyber7-backend-l48kp7h5h-md-limons-projects-283c7c6c.vercel.app`, port 443/default, base path `/api`, and contains zero credentials, query params, or hash fragments.
4. **Traversal & Encoding Defense:** Path segments undergo validation rejecting `..`, `.`, empty segments, `\`, `/`, null bytes (`%00`), and encoded separators (`%2e`, `%2f`, `%5c`).
5. **Exact Route/Method Matching:** Every request path is matched against regex patterns. Unmatched routes return 403. Disallowed HTTP methods return 405 with explicit `Allow` header.
6. **Body Limit & Streaming Guard:** Maximum payload limit of 2 MB (2,097,152 bytes) is enforced. Content-Length header is verified, and streamed bytes are counted in chunks via `reader.read()`. If bytes exceed 2 MB, the reader is cancelled and request fails with 413. Unsupported content types fail with 415. No upstream fetch is dispatched if body validation fails.
7. **Server-Side Bypass Header Injection:** `x-vercel-protection-bypass` is attached server-side to upstream requests. It is never exposed to browser responses or logs.
8. **Header Sanitization:** Upstream response headers (`Set-Cookie`, `Location`, `Server`, `x-vercel-*`, `Access-Control-*`) are stripped. Only approved headers (`content-type`, `content-length`, `content-disposition`, `vary`, `www-authenticate`) are forwarded.
9. **Redirect Defense:** Upstream fetch uses `redirect: "manual"`. Any 3xx redirect from upstream is intercepted and rejected with 502 to prevent leaking bypass secrets to external domains.
10. **Timeout & Abort Handling:** Enforces a 15-second application timeout combined with client `req.signal`. Returns 504 on upstream timeout and 499 on client abort.
